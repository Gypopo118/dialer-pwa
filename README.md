# Звонилка — PWA-прототип

Тёмный премиальный Android-диалер: клавиатура набора, объединённая история
звонков, карточка контакта, экран звонка. Проект собран как обычная
PWA без сборщика (чистые ES-модули, без npm build) — открывается напрямую
через `index.html` и готова к дальнейшей упаковке в APK через ваш workflow
на GitHub (Capacitor/Cordova/Trusted Web Activity — на ваш выбор).

## Как посмотреть локально

Любой статический сервер подойдёт (ES-модули не работают через `file://`):

```
npx http-server . -p 8080 -c-1
# или
python3 -m http.server 8080
```

Открыть `http://localhost:8080` на телефоне или в DevTools с эмуляцией
мобильного экрана.

## Важное ограничение, определившее архитектуру

Браузер (и WebView внутри будущего APK, пока это просто веб-контент) **не
может**:
- читать/писать контакты Android и Google-аккаунта напрямую;
- читать/писать системный журнал звонков (`CallLog`);
- инициировать, принимать или управлять телефонным вызовом ОС;
- стать диалером по умолчанию (`ROLE_DIALER`) без нативного кода;
- управлять громкой связью/микрофоном во время системного звонка.

Всё это — задачи нативного Android-слоя. Поэтому вся интеграция с
устройством спрятана за тремя адаптерами с фиксированным интерфейсом:

| Файл | Отвечает за | Чем заменить в нативной сборке |
|---|---|---|
| `js/adapters/contacts-adapter.js` | Контакты | `@capacitor-community/contacts` или свой плагин над `ContactsContract` / Google People API |
| `js/adapters/call-log-adapter.js` | Журнал звонков | Свой плагин над `CallLog.Calls` (+ `ContentObserver`) |
| `js/adapters/telephony-adapter.js` | Сам звонок, спикер, mute | Свой плагин над `TelecomManager` / `ConnectionService` + `AudioManager` |

Сейчас все три работают на моках (`js/mock-data.js` + `localStorage`), но
весь остальной код — экраны, стор, жесты, вёрстка — уже написан против
финального интерфейса адаптеров. **После нативной реализации методов
внутри этих трёх файлов остальной код менять не нужно.**

Каждый метод, который придётся заменить, помечен в коде комментарием
`TODO(native): ...` с указанием конкретного Android API.

## Структура проекта

```
index.html                 — разметка всех экранов
manifest.webmanifest        — PWA-манифест
service-worker.js           — офлайн-кэш app shell
css/
  tokens.css                 — цвета, радиусы, тени, типографика (по ТЗ)
  base.css                    — сброс, общий layout экранов
  home.css                    — история звонков + блок набора номера
  sheets.css                  — контекстное меню, карточка контакта, экран звонка
js/
  main.js                     — точка входа, связывает экраны
  store.js                    — состояние интерфейса (не данные звонков/контактов)
  mock-data.js                — демо-контакты и демо-история звонков
  recents-model.js            — группировка истории в одну строку на номер
  adapters/                   — см. таблицу выше
  screens/
    home-screen.js             — недавние + клавиатура
    contact-history-screen.js  — карточка контакта + полная история по номеру
    call-screen.js              — входящий/исходящий/активный звонок
  components/
    context-menu.js             — bottom sheet: копировать/добавить/изменить/блок/история
  utils/
    format.js                   — форматирование номеров, времени, длительности
    icons.js                    — инлайн SVG-иконки
    back-stack.js               — жест "назад" как стек history.pushState
    list-scroll-gesture.js      — свайп по истории сворачивает клавиатуру
icons/                       — SVG-иконки приложения (заглушки, см. ниже)
```

## Что уже реализовано (UI и логика на моках)

- Объединение истории звонков в одну строку на номер, с счётчиком всех
  звонков и данными последнего (тип/время/длительность).
- Контекстное меню строки: копировать / добавить в контакты / изменить /
  заблокировать / история звонков (последний пункт открывает карточку
  контакта с полной хронологией по этому номеру).
- Карточка контакта: переименование и изменение номера прямо в шапке
  (contenteditable), кнопка звонка.
- Поиск по именам и номерам (иконка лупы в левом столбце клавиатуры).
- Ручной ввод номера, длинное нажатие на backspace очищает поле целиком,
  долгое нажатие на "0" вставляет "+".
- Жест "назад" (свайп от края экрана) закрывает слои по очереди: контекстное
  меню → карточка контакта → клавиатура (если она открыта) → сворачивание
  приложения — реализовано через `history.pushState`/`popstate`, поэтому
  работает и с системным жестом Android в установленном PWA/TWA, и с
  программной кнопкой "назад" при доработке в Capacitor.
- Свайп/скролл по списку недавних звонков автоматически скрывает
  клавиатуру и показывает полоску "Клавиатура" внизу для быстрого возврата.
- Экран звонка: входящий (принять/отклонить), исходящий/активный
  (завершить), таймер разговора, переключатели громкой связи и "выключить
  мой звук" (mute) — всё на моках `telephony-adapter.js`, наглядно
  показывающих ожидаемое поведение UI.

## Что нужно сделать при переходе на нативную сборку (APK)

1. **Разрешения** в `AndroidManifest.xml` (минимальный набор):
   `READ_CONTACTS`, `WRITE_CONTACTS`, `READ_CALL_LOG`, `WRITE_CALL_LOG`,
   `CALL_PHONE`, `ANSWER_PHONE_CALLS`, `RECORD_AUDIO` (для управления
   маршрутизацией звука), `READ_PHONE_STATE`.
2. **Роль диалера по умолчанию** — запросить `RoleManager.ROLE_DIALER`,
   иначе приложение не сможет ни получать входящие, ни писать в системный
   `CallLog`.
3. **`InCallService` / `ConnectionService`** — обязательны, чтобы
   `telephony-adapter.js` управлял реальным звонком (а не эмулировал его).
4. Реализовать три адаптера согласно таблице выше — по одному плагину на
   каждый (можно оформить как единый Capacitor-плагин с тремя наборами
   методов).
5. Добавить `capacitor.config.json` и платформу `android` вашим
   существующим GitHub workflow — это сознательно оставлено вам, как и
   договаривались.
6. Заменить SVG-иконки в `icons/` на полноценный PNG/adaptive-icon набор
   (сейчас это функциональные заглушки одного стиля, не финальный
   брендинг).

## Известные упрощения текущего прототипа (стоит обсудить)

- Добавление контакта и редактирование номера у контакта без сохранённого
  имени сделаны через `window.prompt()` — самый быстрый способ показать
  поток данных; в финальной версии стоит заменить на экран/шторку в общем
  визуальном стиле.
- "Заблокировать" в контекстном меню сейчас ничего не блокирует физически
  (нет доступа к `BlockedNumberContract` из веб-кода) — просто помечено
  TODO.
- Аватары контактов — плейсхолдеры с инициалами; загрузка реальных фото
  из Google-аккаунта возможна только через People API на нативном слое.
- Хранилище — `localStorage` (просто и достаточно для прототипа); при
  росте объёма истории звонков стоит перейти на IndexedDB.
